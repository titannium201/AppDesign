## 📋 一、产品概述与定位

### 1.1 产品定义

*图：TI 腿部恢复设备 — 可穿戴式腿部按摩/扫描一体机，含多组按摩头与传感器阵列*

TI 腿部恢复智能系统是一款面向高负荷耐力运动者（以跑者为核心）的AI硬件恢复产品。通过近红外光学(mm-DOSI)、接触式热流、力学压测三模态传感器，对下肢肌肉进行扫描评估，结合3D可视化和Garmin式恢复评分，为用户提供"扫描→评估→建议→验证"的闭环恢复体验。

### 1.2 核心价值主张


#### 📊 数据驱动决策

#### 🎯 自动推荐干预

#### ✅ 复测验证效果

参考Garmin Training Readiness的评分方式，输出0-100分的恢复准备度，而非模糊的"有点累"。

根据扫描结果自动推荐按摩部位、力度和时长，降低用户决策成本。

按摩前后对比扫描，量化恢复效果——"这块肌肉恢复分从52提升到78"。

### 1.3 产品形态

| 维度 | 描述 |
| --- | --- |
| 形态 | 可穿戴式腿部设备，环绕式设计，覆盖小腿至大腿下部 |
| 核心传感器 | mm-DOSI近红外光学模块、接触式温度/热流传感器、力学/压力传感器 |
| 执行机构 | 多组按摩头（振动/按压/滚动） |
| 主控芯片 | ESP32（WiFi + BLE双模） |
| 配套App | iOS / Android（首版以iOS为主） |
| 通信方式 | BLE（配网+实时数据）+ WiFi（云端同步） |

> **💡 TI vs 所有竞品的核心差异 = "评估能力"

  TI的三模态扫描填补了这个空白：

  • 竞品：用户自己判断"小腿酸"→选档位→按下去→不知道有没有用

  • TI：设备扫描→显示"右腓肠肌CRS 62/100"→自动推荐→复测验证"提升到78"

  用"专业级判断＋自动执行"填补泡沫轴太敷衍、人工按摩太耗时、自购设备不会用之间的空白。**

## 📡 六、M2 设备配网（BLE Provisioning）

### 6.1 V1方案：仅BLE Provisioning

1. 用户体验最优：不需要切换WiFi，手机通过蓝牙直连ESP32发送WiFi凭据
2. 成功率最高：95%+成功率（vs SoftAP约90%）
3. 安全性最好：Curve25519 + AES256加密
4. 开发资源集中：只维护一条配链路，减少调试复杂度

首版只做一种配网方式：BLE Provisioning（乐鑫官方推荐方案）。原因：

### 7.3 从比赛成绩计算VO2max（VDOT方法）

> **💡 为什么比赛成绩是核心字段？

  Jack Daniels的VDOT（VO2max Run Performance Index）是跑者体能的黄金标准：

  • 输入：任意距离的全全力比赛成绩（5K/10K/半马/全马）

  • 输出：VDOT值 → 对应VO2max估算值 → 推导E/M/T/I/R五种训练配速区间

  • 比用户自报"我是高水平"准确得多

  参考：悦跑圈已内置此算法，我们的差异在于将VDOT与恢复评分联动——高VDOT用户的恢复基准和预期不同。

  示例：全马3:00:00 → VDOT ≈ 51 → VO2max ≈ 58 ml/kg/min → 属于精英业余水平

  全马4:30:00 → VDOT ≈ 35 → VO2max ≈ 40 ml/kg/min → 属于健康跑者水平**

### 8.6 力学压测采集

| 指标 | 计算方式 | 含义 |
| --- | --- | --- |
| LFR 加载力增长率 | LFR = ΔF / Δt | 标准加载下组织反作用增强程度（偏紧/偏硬趋势代理） |
| SR 应力松弛率 | SR = (F_peak - F_hold_end) / F_peak × 100% | 持续按压下组织能否逐渐放松 |
| FRT90 力信号恢复时间 | FRT90 = t when F(t) ≥ F_min + 90% × (F_stable - F_min) | 释放后力信号恢复到稳定轻触平台90%的时间 |

| 参数 | 建议值 |
| --- | --- |
| 轻触基线力 | 0.2-0.5N |
| 目标峰值力 | 5N |
| 安全上限 | 7N |
| 保持时间 | 3-5秒 |
| 释放后记录时间 | 3-10秒 |
| 采样率 | ≥100Hz |
| 重复次数 | 每个点测3次，取中位数 |
| 质控规则 | CV > 15% 时建议重测 |

   + 0.10 × User Feedback Score    // 用户主观酸紧疼反馈

### 10.2 报告示例

> **💡 下肢整体恢复准备度：68 / 100

  状态：中等，可以训练，但不建议加码

  主要拖累项：

  1. 右腓肠肌 CRS 低于近期跑步后常态

  2. StO₂恢复斜率较个人参考慢 32%

  3. FRT90较左侧延长 18%

  4. 今日跑步负荷高于近期常态 28%

  建议：

  • 明天适合轻松跑或低强度有氧

  • 不建议安排冲刺、爬坡或高强度间歇

  • 优先按摩右腓肠肌和胫骨前肌

  • 如果使用按摩功能，推荐"跑步后恢复"模式，力度3/5级，15分钟**

### 10.3 科学依据声明

> **💡 科学边界声明（必须出现在报告中）

  本系统的评估不构成医学诊断。三个传感方向分别对应耐力运动恢复中的三个可测量侧面：

  • mm-DOSI/NIRS → 氧供、氧耗、血容量、微循环反应

  • 皮肤温度/热流 → 代谢产热、皮肤血流调节、散热趋势

  • 力学压测 → 肌肉张力、组织黏弹性、局部紧张

  它们不覆盖肌肉恢复的全部机制，但分别提供了可量化、可重复、可追踪的客观数据维度。

  最终产品表达不是："你这块肌肉损伤了"

  而是："右腓肠肌综合恢复分62/100，低于你近期跑步后的常态。"**

```
CREATE TABLE scans (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID REFERENCES users(id),
  device_id VARCHAR(64),
  
  scan_type VARCHAR(20) NOT NULL,           -- 'baseline'/'post_exercise'
  sport_type VARCHAR(20),                  -- 'running'/'cycling'
  exercise_duration_min INTEGER,
  rpe INTEGER,                             -- 1-10 主观疲劳感
  
  -- 整体评分
  overall_score INTEGER,                   -- 0-100
  confidence VARCHAR(20),                  -- 'high'/'medium'/'low'/'invalid'
  
  -- 各肌群CRS评分 (JSONB)
  muscle_scores JSONB,                     -- {"right_gastrocnemius":{"crs":62,"ors":58,"mrs":65,"trs":74}, ...}
  
  -- 原始数据摘要 (JSONB)
  optical_data JSONB,                      -- StO2/HbO2/HHb/HbT per muscle
  thermal_data JSONB,                      -- Tskin/delta_Tskin/q/delta_q per muscle
  mechanical_data JSONB,                   -- LFR/SR/FRT90 per muscle
  recovery_data JSONB,                     -- T50/T90/recovery_slope (if applicable)
  
  -- 左右对比
  laterality_summary JSONB,
  
  -- 建议
  recommendations TEXT[],
  
  started_at TIMESTAMPTZ,
  completed_at TIMESTAMPTZ,
  created_at TIMESTAMPTZ DEFAULT NOW()
);
CREATE INDEX idx_scans_user_created ON scans(user_id, created_at DESC);
CREATE INDEX idx_scans_type ON scans(scan_type);
```
